01 / 方向

验证对象是芯片上的能量路径，不只是功能正确

我做 GPU / 芯片功耗验证：关注不同负载下功耗如何随时钟、电压、门控和电源状态变化，以及这些变化能否被测试、记分板和覆盖率抓住。此前做过 SoC 验证、高速互连验证、回归基础设施与验证工具。熟悉 PCIe、RDMA、存储层次、MMU、虚存、序、重试与调度。当前优先项是功耗与性能的交叉、时钟/电压/功耗域、门控、遥测，以及工作负载驱动的功耗行为。

  • 主战场 GPU / 芯片功耗
  • 方法偏好 需求 → 用例 → 可观测量 → 结果 → 覆盖
  • 调试原则 证据优先，先找第一处有效失败

02 / 方法

先分清 DUT、用例、环境、记分板和基础设施

  1. 需求落到可观测点

    每个功耗需求都要有明确可观测量：轨电压、时钟使能、隔离应答、遥测计数、进入/退出延迟。没有观测点的需求不算可验证。

  2. 症状与根因分开

    高功耗可能是门控失效，也可能是用例没把域关干净，或记分板把 retention 当成 off。没有证据不宣称根因。

  3. 假设必须带验证步骤

    每个假设对应波形、日志或覆盖点。大日志先抽结构化证据再分析：域状态、事件序列、时序窗口。

  4. 回归要能抓住功耗路径

    功能回归通过不等于功耗路径被覆盖。状态转换、非法请求、跨域时序、遥测漂移都要进回归。

    04 / 能力

    验证栈与架构交叉点

    功耗与性能交叉

    同一负载在不同 P-state、电压点和门控策略下的功耗/性能权衡。关注进入退出延迟对吞吐和延迟的影响。

    时钟 / 电压 / 功耗域

    跨域隔离、复位释放顺序、retention 内容完整性、非法跨域访问。时钟树与电源树必须一起看。

    高速互连

    PCIe、RDMA 链路功耗状态与重试、序、调度的交叉。低功耗进入不得破坏 outstanding 事务语义。

    存储层次与 MMU

    虚存、页表走访、缓存一致性流量如何抬升动态功耗。关注空转时不该发生的探听与回填。

    回归与工具

    Python / C++ / SystemVerilog。可调试的回归：pathlib、logging、类型提示；生成代码用确定性工具校验。

    遥测闭环

    RTL 计数、采样窗口与软件读数对齐。遥测延迟、饱和、时钟域跨越都是独立失败模式。

    05 / 联系

    讨论功耗验证问题
